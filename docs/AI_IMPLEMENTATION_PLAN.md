## 1. 着手前に決める必要があること（最優先）

実装に入る前に、次の 2 点の判断が必要です。どちらも、AI 機能を公開できるかどうかに関わります。

> **決定（2026-11-11）**: AI 機能の対象は **18 歳以上**、利用地域は **日本だけ** とします。AI パネルと README にこの条件を明記し、サーバーでは日本（`JP`）からのリクエストだけを受け付けます。

### 1.1 利用者の年齢（Gemini API 規約）

Gemini API の追加利用規約（[Gemini API Additional Terms of Service](https://aistudio.google.com/docs/terms)、2026-03-23 施行）では、次のように定められています。

- 利用できるのは 18 歳以上
- **18 歳未満に向けた、または 18 歳未満が使う可能性が高いアプリ・サイトでは利用できない**

NextScope は誰でも見られる学習サイトです。そのため、想定利用者に 18 歳未満が含まれるかを決める必要があります。

- 含まれない（対象は社会人・大学生など）と判断する場合
  - 利用者の想定をサイト上に明記し、AI パネルにも案内を出す
- 含まれる場合
  - 公開サイトで AI 機能を有効にしない（ローカルや限定公開での利用に留める）か、計画を見直す

### 1.2 無料枠のデータの扱いと、利用地域

- 無料枠（Unpaid Services）の入力と出力は、Google の製品改善に使われます。アカウントとの紐付けを外したうえで、**人が読むことがあります**。規約は、機密情報や個人情報を送らないよう求めています。
  - 対応: 送る内容は、教材の公開情報・登録済みのコード・検証済みの実行記録の要約と、利用者が入力した質問に限る。質問は送る前にサーバーで検査する（§6.5）。画面には「入力内容は Google に送られ、製品改善に使われることがある。個人情報を入力しない」と表示する。
- EEA・スイス・英国の利用者にサービスを提供する場合は、有料サービスしか使えません。EEA などにも日本語の利用者はいるため、「日本語の学習者が対象」と書くだけでは条件を満たせません。
  - 対応（決定）: 利用地域は日本だけとする。Vercel が付ける国コードのヘッダー（`x-vercel-ip-country`）が `JP` のときだけ AI のリクエストを受け付け、それ以外は断ってパネルに案内を出す（断る国を並べる方式ではなく、許可する国だけを決める方式）。ヘッダーがない・不正などで判定できないときも、本番では断る（§6.1）。IP アドレスから推定した国なので、VPN などで外れることがある限界は残る。

- `observed`: 自分のコードで実際に計測・記録したステップ（`durationMs` などの計測値や、サーバーが返した結果があるもの）
- `conceptual`: それ以外のステップ（フレームワーク内部の処理など）と、`source: "model"` の記録全体

Phase 2 では、どのステップを計測したかを、推測ではなく明示的に持たせます（例: `FlowStep` に区分を表す項目を足す、または記録を作る関数の側で区分を返す）。

**モデルの選び方**: モデルは `GEMINI_MODEL` に設定し、コードには固定しません。初期値の候補は、Flash-Lite 系の無料枠対象モデルです（`gemini-3.5-flash-lite` など）。実装を始めるときに AI Studio で無料枠の数値を確認し、決めます。

### 5.2 SDK `@google/genai`

- 最新は 3.1.0（2026-11-10 更新）で、**Node.js 22 以上が必要**です。[js-genai](https://github.com/googleapis/js-genai)
- 呼び出し方は次のとおりです。
  - `new GoogleGenAI({ apiKey })` → `ai.models.generateContent({ model, contents, config })`。回答は `response.text`
  - `config` には `systemInstruction`、`maxOutputTokens`、`abortSignal`、`httpOptions.timeout`（ミリ秒）を渡せる
  - エラーは `ApiError` で、HTTP ステータスは `error.status`
- **`abortSignal` で止まるのは、こちら側の待機だけです。** Gemini 側の処理は止まらず、利用枠も消費されます。そのため、入力の長さと `maxOutputTokens` の上限で抑えます。
- 旧 SDK `@google/generative-ai` は、2025-04 から更新されていません。使いません。

### 5.3 利用制限の保存先の候補

| 候補                                                                   | 無料枠                       | 評価                                                                                                                                                                                       |
| ---------------------------------------------------------------------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Upstash Redis**（Vercel Marketplace 経由も可）+ `@upstash/ratelimit` | 月 50 万コマンド・250 MB     | **第一候補。** サーバーレス向けで、HTTP で使える。料金ページには「クレジットカードを登録すると従量課金に切り替わる」とある。上限を超えたときに止まるのか、登録時にカードが必要かは、未確認 |
| Vercel KV                                                              | —                            | 提供終了。Upstash に移行済み                                                                                                                                                               |
| Vercel WAF Rate Limiting                                               | Hobby でルール 1 つ・IP 単位 | 補助的な防御。カウンターがリージョンごとで、1 日の上限には使えない                                                                                                                         |
| Vercel Edge Config（Global Config）                                    | 書き込み 100 回              | 書き込みの反映が遅く、カウンターには向かない                                                                                                                                               |
| Supabase                                                               | DB 500 MB                    | 制限の処理を SQL で自作することになり、手間が大きい                                                                                                                                        |

注意点が 2 つあります。

- `@upstash/ratelimit` は、保存先が応答しないと、リクエストを**通してしまう**（フェイルオープン）のが既定です。NextScope では、**応答しなければ AI を止める**（フェイルクローズ）ように実装します。
- **どの候補も、「上限を超えても自動では課金されない」ことを公式情報で確認できていません。** カードを登録しない運用を前提にし、登録時に確認します。確認できなければ、AI 機能は公開しません（仕様 §5.3）。

## 6. 設計方針

### 6.1 全体の流れ

```text
教材ページ（Server Component: lesson-page.tsx）
  └─ AI パネル（Client。Sheet で開く。開いただけでは何も送らない）
        │  利用者が「送信」を押したときだけ
        ▼
POST /api/ai/explain（Route Handler）
  1. 機能フラグ（NEXTSCOPE_AI_ENABLED）・キー・保存先の設定を確認 → 欠けていれば 503
  2. 提供地域の確認（§1.2。日本だけ）→ 日本以外、または判定できなければ 403 と案内
  3. 本文のサイズ・JSON・入力値の検証（教材 ID・mode・質問の長さ）→ 400 / 413
  4. 送る内容の検査（§6.5）→ 個人情報や秘密情報らしいものがあれば 400 と案内
  5. 教材の内容・コード・実行記録は、サーバーで ID から引くか検証する（クライアントから送られた本文は信頼しない）
  6. 短時間のキャッシュを確認（キーは下の表）→ あれば、Gemini の利用枠を使わずに返す
  7. 利用制限（サイト全体の 1 日の上限、送信元ごとの上限）→ 429
  8. Gemini を 1 回呼ぶ（タイムアウトあり・自動の再試行なし）
  9. 回答と、許可済みの参照（教材リンク・ファイル）だけを返す

  ※ 6・7 で保存先が応答しない、またはエラーになったときは、その時点で 503 を返す（フェイルクローズ）。
     キャッシュからの返却も含めて、AI の応答はすべて止める
```

**地域の判定（手順 2）**: 本番では、国コードのヘッダーが `JP` のときだけ受け付けます。ヘッダーがない・空・形式が正しくない・不明を表す値のときも、対象外として断ります（安全側に倒す）。開発中（`NODE_ENV !== "production"`）だけ、判定を省きます。この分かれ方は自動テストで確かめます。

**保存先の障害（手順 6・7）**: キャッシュと利用制限は、同じ保存先（Upstash Redis を想定）に置きます。保存先に障害があるときは、キャッシュから返せる回答があっても返しません。理由は 2 つです。

- 動きを「保存先が使えなければ AI は止まる」の 1 つにそろえ、§6.2・§6.3 と食い違わないようにするため
- 障害中は、送信元ごとの上限を確かめられないため

キャッシュから返すときに Gemini の利用枠を使わないのは、Gemini を呼ばないからです。送信元ごとの上限も数えません（#65 で決定）。

**例外：回答をキャッシュに保存できなかったとき**は、止めずに回答を返します。この時点では、利用制限の確認も Gemini の呼び出しも終わっていて、利用枠も消費済みだからです。止めても安全にはならず、利用者の枠が無駄になるだけです。

**キャッシュのキー**には、前後の空白を除いた質問をそのまま使います。大文字・小文字や空白の数はそろえません。そろえると、意味の違うコードの質問（`GET()` と `get()` など）に同じ回答を返してしまうためです。

**キャッシュのキー（仕様 §5.2）**: 前の回答を、別の実行や別のコードに返さないよう、次のすべてが一致したときだけ使います。

| mode              | キーに含めるもの                                                      |
| ----------------- | --------------------------------------------------------------------- |
| `context_tutor`   | 教材 ID・mode・正規化した質問・プロンプトの版・モデル ID              |
| `code_explain`    | 上に加えて、登録済みのコード参照（ファイルと行の範囲、またはその ID） |
| `runtime_explain` | 上に加えて、検証済みの実行記録の要約のハッシュ                        |

- 共有してよいのは、教材の公開情報だけから作られる回答に限ります。実行記録を含む回答（`runtime_explain`）は、その実行をした利用者にしか返しません（キーに、匿名のセッション ID を含めます）。
- 質問の本文そのものはキーに入れず、ハッシュにします。キャッシュの保存期間は短くします（例: 1 時間）。

### 6.2 守ること（仕様 §0・§5・§7）

- Gemini はサーバーでだけ呼ぶ。キーには `NEXT_PUBLIC_` を付けず、`server-only` のモジュールでだけ読む
- 教材の閲覧・デモの操作・ノードの選択では、API を 1 回も呼ばない。呼ぶのは、ボタンが押されたときだけ
- 429 やタイムアウトのとき、自動で再試行しない。`Retry-After` があれば画面に表示し、再試行は利用者に任せる
- 機能フラグ・キー・保存先のどれかが欠けている、または障害があるときは、AI パネルに案内を出すだけにする。教材のページ全体はエラーにしない
- ログに残すのは、教材 ID・mode・結果の状態・所要時間だけ。質問の本文とキーは残さない
- 回答には「AI が生成した解説」と表示する。Runtime Detective では「観測したこと」「一般的な仕組み」「推測」を分けて表示する

### 6.3 利用制限

- **サイト全体の 1 日の上限**（`NEXTSCOPE_AI_DAILY_REQUEST_CAP`）を、いちばん大事な安全装置にする。Gemini の制限はプロジェクト単位なので、全利用者で共有される。数値は、AI Studio で確認した RPD より小さくする
- **送信元ごとの上限**（`NEXTSCOPE_AI_PER_SOURCE_DAILY_CAP`）は、補助的な防御として扱う。仕様 §5.3 は「IP アドレスだけに頼らない」ことを求めているため、次を組み合わせる（§9 #9）
  - IP アドレスのハッシュ: 取得元は、Vercel が設定するヘッダー（`x-forwarded-for` の先頭など）に限る。利用者が自由に付けられるヘッダーは信頼しない。ハッシュは、サーバーだけが持つ秘密の値を使った HMAC-SHA256 にし、その日の日付も混ぜる。IP アドレスは、そのままの形では保存しない
  - 署名付きの匿名 Cookie（`HttpOnly`・`Secure`・`SameSite=Lax`、有効期限は 1 日）: 同じ IP を使う人どうし（学校や会社など）が巻き込まれにくくなる。ただし、Cookie を消せば回避できる。使う場合は、何を保存するかと保存期間を画面に書く
  - 限界: IP アドレスを変えたり Cookie を消したりすれば、送信元ごとの上限は回避できる。最後の歯止めは、**サイト全体の上限**とする
- **同時に来たリクエストでの数え漏れを防ぐ**: 枠の確認と消費を 1 回の操作で行う（Redis の `INCR` と有効期限の設定、または `@upstash/ratelimit` の `limit()`）。「数を読む → 確かめる → 増やす」を別々に行わない。Gemini の呼び出しに失敗しても、消費した枠は戻さない（安全側に倒す）
- 本番（`NODE_ENV=production`）で保存先が設定されていない場合は、AI を無効にする。開発中だけ、メモリでの簡易な制限を許す
- 日付の区切りは日本時間の 0 時とする（§9 #6）。Gemini の RPD は太平洋時間の 0 時（日本時間の 16 時または 17 時）にリセットされるため、サイト全体の上限は、日をまたいでも Gemini の RPD を超えない値にする

### 6.4 環境変数（`.env.example` にはキー名だけを書く）

```dotenv
GEMINI_API_KEY=
GEMINI_MODEL=
NEXTSCOPE_AI_ENABLED=false
NEXTSCOPE_AI_DAILY_REQUEST_CAP=20
NEXTSCOPE_AI_PER_SOURCE_DAILY_CAP=3
```

### 6.5 送る内容の検査（仕様 §0・§5.4）

画面の注意だけには頼らず、送る前にサーバーで検査します。

- 教材の本文・コード: サーバーで、登録済みのものから組み立てる。クライアントから送られたコードや本文は使わない
- 実行の記録: 計測値・ステップの ID・結果の状態だけを送る。フォームに入力した値・Cookie・トークン・ヘッダーは入れない
- 質問: 文字数に上限を設ける。メールアドレス・電話番号・クレジットカード番号らしい数字の並び・API キーらしい文字列（`sk-`、`AIza` で始まるものなど）・長いランダムな文字列を検出したら、送らずに「個人情報や秘密情報らしい内容が含まれています」と案内する
- 限界: 検出はパターンによるもので、氏名や住所などの文章をすべて見つけることはできない。そのため、画面の注意も併せて表示する。検出のルールは、自動テストで確かめる

- 入力した値（名前）は記録に入れない

**実行記録の検証**（仕様 §6「traceId は利用者セッションと紐づけて検証する」）

**Phase 2 からは、署名付きの匿名 Cookie（§6.3）が必須です。** 実行記録をセッションと結び付けて検証することと、`runtime_explain` の回答を本人にだけ返すことは、どちらもこの Cookie を前提にしています。Cookie がない、または署名が正しくない場合、`runtime_explain` は 400 を返し、画面には「ページを読み込み直してから、もう一度実行してください」と案内します。`context_tutor` は Cookie がなくても使えます。この Cookie は「送信元ごとの上限」にも使います（§9 #9）。

- Server Action が、記録と一緒に**署名付きのトークン**を返す。トークンには、教材 ID・実行 ID（`traceId`）・匿名のセッション ID・発行時刻・記録の要約のハッシュを入れる。署名には、サーバーだけが持つ秘密の値を使う（既存の `jose` を使い回せる）
- AI の API は、次をすべて確かめる。1 つでも合わなければ 400 を返す
  - 署名が正しい
  - 教材 ID がリクエストと一致する
  - セッション ID が、リクエストの匿名 Cookie と一致する
  - 有効期限内（例: 10 分）
  - 送られてきた要約のハッシュが、トークンの中のハッシュと一致する
- **信頼する範囲**: `observed` として扱うのは、サーバーが計測して署名したステップだけ。ブラウザで計測したもの（クリックから画面が更新されるまでの時間など）は、改ざんできるため「ブラウザからの申告」として区別して表示する。AI には、申告であることを伝える
- 同じ実行に対する重複した問い合わせは、§6.1 のキャッシュで抑える

## 10. リスク

- **規約**: 18 歳未満の利用、EEA などでの無料枠の利用。対象を 18 歳以上・日本だけに限ることで対応する（§1）。年齢は自己申告に頼るため、画面での明記が欠かせない
- **無料枠の共有**: 制限はプロジェクト単位。サイト全体の上限がなければ、少数の利用者が枠を使い切る
- **無料枠の変更**: 対象のモデルと数値は変わりやすく、廃止も多い。モデル ID は環境変数で差し替えられるようにする
- **課金**: 保存先の無料枠について、「超えても課金されない」ことを確認できていない。カードを登録しない
- **フェイルオープン**: 利用制限の保存先の障害で制限が効かなくなる。フェイルクローズで実装する
- **中断しても枠は減る**: タイムアウトしても Gemini 側の処理は止まらない。入力と出力の長さで抑える
- **データの扱い**: 無料枠の入力は人が読むことがある。送るのは、教材の公開情報・登録済みのコード・検証済みの実行記録の要約・検査を通った質問だけにする（§6.5）。検査はパターンによるもので、すべての個人情報は見つけられないため、画面の注意も表示する
- **地域の判定の限界**: 国コードは IP アドレスからの推定で、VPN などで外れる（§1.2）
- **送信元ごとの上限の限界**: IP アドレスの変更や Cookie の削除で回避できる。同じ IP を使う人どうしが巻き込まれることがある（§6.3）
- **キャッシュの取り違え**: キーが足りないと、別の実行や別のコードに前の回答を返す。キーの組み立てを自動テストで確かめる（§6.1）
- **Node のバージョン**: SDK と Vitest は Node 22 以上が必要。Vercel の設定と合わせる
- **既存の体験の維持**: AI のコードは Client の bundle が大きくならないようにする（パネルは開いたときに読み込む）。Cache Components の静的シェルを壊さない（教材ページは静的なままにし、AI は Client から API を呼ぶ）
